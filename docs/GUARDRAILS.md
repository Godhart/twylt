# Guardrails — TWYLT 1.1.0

TWYLT предоставляет опциональные механизмы типового контроля для защиты от
неосторожного и некорректного использования. Автор тула отвечает за применение
этих механизмов и безопасность бизнес-логики. Произвольные обращения Python и
внешних программ контролируются ОС; TWYLT не перехватывает их и не является sandbox.
Проверка пути также не устраняет гонки с другим процессом, который меняет ФС.

## Окружение

| Переменная | Семантика |
|---|---|
| `TWYLT_GUARDRAILS` | `0` по умолчанию; `1` включает политику |
| `TWYLT_WORKSPACE_ROOT` | Абсолютный существующий корень бизнес-путей |
| `TWYLT_ALLOWED_CWD` | Дополнительный абсолютный существующий корень для cwd, включая все подкаталоги |
| `TWYLT_DISABLE_NETWORK` | `0` по умолчанию; при включённых guardrails значение `1` запрещает сеть через API |
| `TWYLT_INCIDENT_LOG` | Абсолютный путь журнала вне workspace и используемого транспортного корня; иначе stderr |

Boolean-параметры принимают `0/1`, `false/true`, `no/yes`, `off/on`, без учёта
регистра. Другие значения — ошибка конфигурации; пустая строка не означает false.
Параметры задаёт доверенное окружение процесса, они не берутся из входного JSON.

`describe`, help и version не требуют конфигурации guardrails. Вход JSON через
CLI/stdin без файловых операций не требует workspace. Файловая операция при
включённых guardrails требует настроенного корня; отказ не отключает политику.

## Файловый транспорт и cwd

Допустим cwd внутри workspace либо внутри `TWYLT_ALLOWED_CWD`, включая вложенные
каталоги любой глубины. Сравнение выполняется по компонентам пути: `/runs-other`
не входит в `/runs`. Корни и их предки должны быть настоящими каталогами, без
symlink/junction. Файлы транспорта проверяются на ссылки, hardlinks, специальные
файлы и переходы устройств. Транспортные input_path/output_path должны лежать
непосредственно в фактическом cwd; произвольные пути через эти атрибуты запрещены.

Проверки выполняются перед удалением старого output.json, перед чтением input.json
и перед записью output.json. Атрибуты класса не меняются. Разрешение cwd не
разрешает бизнес-логике читать или менять этот каталог.

```bash
export TWYLT_GUARDRAILS=1
export TWYLT_WORKSPACE_ROOT=/srv/workspace
export TWYLT_ALLOWED_CWD=/srv/toolhub-runs
# cwd /srv/toolhub-runs/request-1/python допустим
```

## API для автора тула

```python
from twylt.guardrails import Workspace, check_network

# В собственной бизнес-логике:
check_network(self.name)  # перед запросом или запуском сетевой команды
with Workspace(self.name) as ws:
    path = ws.resolve(data.path)
    # /file и file — виртуальные пути от workspace при настроенном корне.
    # Перед изменением корня или рекурсивной мутацией:
    ws.protect_root(path)
    ws.tree(path)
    path.write_text(data.text, encoding="utf-8")
```

`Workspace.inspect(path)` проверяет физический путь, `resolve(value)` — бизнес-путь,
`virtual(path)` возвращает представление относительно workspace. `Policy` позволяет
проверить конфигурацию, сетевой доступ и пути транспорта без собственного Tool.
При включённой политике запрещены `..`, ссылки в пути, hardlinks, специальные файлы,
переход устройства и мутация корня через protect_root(). Проверки вызываются явно;
наличие Workspace в импортах само по себе не ограничивает вызовы open/subprocess.

При выключенной политике inspect/protect_root не ограничивают доступ, сеть разрешена.
Если workspace задан, сохраняется виртуальное отображение `/file` в этот корень;
без workspace относительные пути относятся к cwd, абсолютные — к ФС хоста.
Валидация контракта, URL, аргументов и лимитов инструмента остаётся включённой.

Отказ: WorkspaceDenied; ошибочная конфигурация: GuardrailsConfigError. Tool.run()
возвращает exit code 6 и JSON-ошибку guardrails_error, source=twylt. Отказ включает
code и incident_id. Событие отказа пишется JSONL в журнал или stderr; stderr может
содержать событие и отдельный JSON ответа об ошибке. Остальные exit codes сохранены.

## Общие модели

`from twylt import ContractModel` — удобная базовая модель Pydantic с extra=forbid
и allow_inf_nan=False. Использование необязательно; обычные BaseModel по-прежнему
поддерживаются, TWYLT сохраняет свою строгую проверку неизвестных полей.
